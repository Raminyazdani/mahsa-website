# معماری محتوا و قرارداد محصول

منبع حقیقت دو JSON هم‌ساختار انگلیسی و آلمانی است. هر دو مجموعهٔ ادغام‌شدهٔ واقعیت‌های دو CV را نگه می‌دارند. ساختار اصلی، کلیدها، nesting، نوع مقدارها و قرارداد رشتهٔ خالی یا `null` تغییر نکرده‌اند و بازطراحی نسخهٔ ۲ هیچ بایتی از این دو فایل را عوض نکرده است.

```text
content/mahsa-cv.{en,de}.json
        ↓ load.ts
validate.ts + source/schema.ts
        ↓ adapter.ts
WebsiteContent در model.ts
        ↓ generated.ts (مشتق‌شده در هر build/typecheck)
src/render (HTML ایستا) + src/app (رفتار مرورگر) + src/cv.ts (CV کامل)
```

فقط `src/content` با شکل خام داده آشناست. UI از `src/content/model.ts` نوع و از `src/content/generated.ts` دادهٔ معتبر می‌گیرد. فایل generated محتوای دستی دوم نیست و نباید ویرایش شود. `npm run content:check` این مرز را اجرا می‌کند: هر import از adapter/load/validate/source یا خود JSON بیرون از `src/content` خطا است. هیچ JSON خام، provenance یا PDF ورودی به `dist` کپی نمی‌شود.

قرارداد `WebsiteContent` دسته‌های تحصیل، سابقه، پروژه، مهارت‌های تو در تو، زبان، آموزش، انتشار، معرف و علاقه را نگه می‌دارد. تعداد آیتم‌ها سقف ندارد. empty collection و بخش اختیاری خالی در adapter حذف می‌شوند و فهرست ایستگاه‌ها (`stationsFor` در `src/app/appearance.ts`) فقط از بخش‌های دارای داده ساخته می‌شود؛ بنابراین بخش خالی نه در Portfolio، نه در نقشهٔ Laboratory، نه در command palette دیده می‌شود. اعتبارسنجی همهٔ خطاها را با JSON Pointer دقیق گزارش می‌کند و مقدار ساختگی جایگزین نمی‌کند.

## کلیدهای پایدار و متادیتای ظاهر

دسته‌ها و گروه‌های مهارت در مدل علاوه بر `id` و `title` یک `key` ترجمه‌نشده دارند: نام همان کلید در JSON منبع. ظاهر هر چیز (کانال فلورسنت، شکل ظرف روی میز، دستگاه گروهی، دستگاه مفهومی پروژه) فقط در `src/app/appearance.ts` و بر اساس همین کلیدها/شناسه‌ها تعیین می‌شود:

- `categoryAppearance(key, index)` → کانال + ظرف (duran، flask، falcon، vial). دستهٔ ناشناخته ظاهر پیش‌فرض بر اساس ترتیب می‌گیرد.
- `groupAppearance(key)` → دستگاه نمای Group instruments (terminal، monitor، chromatogram، helix، plate، cycle، rack، tubes). پیش‌فرض: tubes.
- `projectAppearance(id)` → photolithography، expression یا specimen عمومی.

این فایل هیچ متن CV ندارد؛ فقط نگاشت کلید → ظاهر است. افزودن دسته، گروه یا پروژهٔ تازه در JSON بدون تغییر کد کار می‌کند. شناسهٔ مهارت‌ها در دو زبان متفاوت است (از متن ساخته می‌شود)؛ برای حفظ انتخاب هنگام تعویض زبان، مهارت با «گروه + ترتیب» نگاشت می‌شود و ذخیره‌ها با قالب `skill:<groupId>~<index>` نگه داشته می‌شوند.

متن رابط کاربری (عنوان ایستگاه‌ها، برچسب کنترل‌ها، پیام‌ها) فقط در `src/app/i18n.ts` و برای هر دو زبان کامل است. هیچ واقعیت CV در آن نیست.

## ویرایش محتوا

برای ویرایش متن یا افزودن، حذف و جابه‌جایی آیتم‌های پشتیبانی‌شده، فقط JSON زبان مربوط را تغییر دهید؛ برای حفظ پوشش واقعی، تغییر متناظر زبان دیگر را هم اعمال کنید. سپس:

```powershell
npm run check
```

به بخش‌های خالی واقعیت ساختگی اضافه نکنید. تاریخ مورد انتظار پایان‌نامه را به پایان قطعی تبدیل نکنید. سطوح R و Python متوسط و سطح آلمانی B1-B2 هستند و در نوارهای زبان دقیقاً به صورت بازهٔ B1–B2 نمایش داده می‌شوند (نه یک عدد یا درصد ساختگی). عنوان یک دستهٔ ذخیره‌سازی، مهارت اضافه‌ای را اثبات نمی‌کند؛ labelهای ارائه در `source/presentation.ts` بر اساس اقلام واقعی دسته نوشته شده‌اند.

تغییر هم‌معنای schema در همین مرز انجام می‌شود. نمونهٔ اجرایی `source/migrate.ts` شکل `{ formatVersion: 2, cv: <ساختار اصلی> }` را به مدل یکسان تبدیل می‌کند. آزمون migration برابری کامل مدل و HTML CV را ثابت می‌کند؛ UI یا renderer برای این تغییر عوض نمی‌شوند.

## CV و PDF

CV در `src/cv.ts` فقط مدل پایدار را مصرف می‌کند. تمام مجموعه‌ها را از داده می‌سازد و به state جست‌وجو، فیلتر، حالت Laboratory/Portfolio، تم یا Focus mode وابسته نیست. چاپ: A4، متن تیره روی سفید، حاشیهٔ ۱۴/۱۵/۱۶ میلی‌متر (بالا/کنار/پایین)، متن پایه ۹٫۴pt، نام و شمارهٔ صفحه در پاورقی. طول دو صفحه سقف اجباری نیست.

HTML و چاپ در هر build تازه می‌شوند؛ PDF قابل دانلود نیازمند بازتولید جداگانه است (`cv:pdf` → `cv:verify` → مشاهدهٔ همهٔ صفحه‌ها → `cv:stamp`). build فقط PDFی را کپی و لینک می‌کند که stamp معتبر و SHA-256 سازگار با مدل، بایت‌های JSON منبع، `src/cv.ts`/`src/cv.css`، عکس و فونت‌های woff2 فعلی داشته باشد. PDF قدیمی با هشدار از `dist` حذف می‌شود و CV کامل HTML همچنان موجود است. metadata در `content/cv-pdf-artifacts.json` فاقد متن رزومه است.

`docs/content-coverage.json` شواهد مشتق‌شدهٔ مسیر هر فیلد واقعیِ غیرخالی از منبع به مدل و HTML کامل CV را ثبت می‌کند (در وضعیت فعلی ۱۳۱ واقعیت برای هر زبان).

در خروجی استاتیک، تغییر JSON پس از build دوباره دیده می‌شود. بارگذاری زندهٔ JSON از پروژهٔ قدیمی یا سرور خارجی وجود ندارد.

## سابقه

شواهد انتقال اولیه (`source-preservation.json`، `content-preservation-status.json`، `asset-replacements.json`) و اسناد نقد/QA طراحی نسخهٔ ۱ دست‌نخورده در `_archive/design-v1-2026-11-14/docs/` نگه داشته شده‌اند. آن baseline برای فونت‌های قدیمی (Manrope/Source Sans 3) بود و در نسخهٔ ۲ کاربرد اجرایی ندارد؛ منشأ فونت‌های فعلی در `public/fonts/provenance.json` است.
